## 4. 本阶段的技术决定

- 新建小型 Python / Qt 应用，复用系统已有运行时。现有 CopyQ 等工具具备更广功能，但其界面与功能范围大于当前需求；本次选择减少首版范围，代价是自行维护原生集成和后续平台适配。
- 数据和界面与 X11 集成分开，后续 Windows/macOS 需要各自实现平台层。
- 第一阶段只保存文本表示，按完整文本去重；富文本不同表示的存储与比较在第二阶段实现，不宣称本版保留原格式。
- 快捷键默认 Ctrl+Alt+V；注册冲突时提示用户，并保留原有有效快捷键。
- 回填剪贴板不产生历史副本；无法确认目标焦点时不发送粘贴按键。
- 已识别终端中的多行文本只复制。编辑器内嵌终端、网页终端没有可靠识别，用户应使用「仅复制」。
- PyQt5 依赖采用 GPLv3 / 商业双许可，见 [官方说明](https://www.riverbankcomputing.com/software/pyqt)。当前为本机源码运行版，公开分发前需确定许可和打包方案。

## 6. 修复记录：0.1.1 中文无法输入

用户反馈：微信复制正常，但搜索框不能输入中文。

定位：本机配置为 IBus，插件已安装且输入法套接字可连接，但沙箱内无法看到宿主输入法进程的 PID。Qt 5 的直接连接代码使用 `kill(pid, 0)` 检查进程，因此误判输入法不可用。此前注入 Qt 输入法事件的测试未覆盖这条真实连接路径。

修复：在 QApplication 初始化前检测当前会话的 `org.freedesktop.portal.IBus` 服务；服务可用且用户选择 IBus 时，启用 Qt 支持的 `IBUS_USE_PORTAL` 连接方式。门户不存在时保持原行为，不更改系统输入法配置、不重启输入法服务、不覆盖显式环境设置。

验证：独立测试窗口只使用自造拼音，不读写剪贴板。通过 X11 实际按键输入 `nihao`，修复前只得到英文，修复后收到预编辑事件并用空格选词得到“你好”；另验证组合期间 Enter 不会触发粘贴。已重启当前应用以加载修复，历史库未迁移或清空。

重启时同时修复单实例锁的进程命名空间问题：改用 Linux 内核文件锁，退出时自动释放，不再依靠残留文件中的 PID 判断进程是否存在。强制停止后重新启动和重复启动唤起均已验证；不删除或重建历史数据库。

代码依据：[Qt 5.15 IBus 输入上下文源码](https://raw.githubusercontent.com/qt/qtbase/5.15/src/plugins/platforminputcontexts/ibus/qibusplatforminputcontext.cpp)。核查于 2026-09-15；相关逻辑为 `shouldConnectIbusPortal()` 和 `createConnection()`。
